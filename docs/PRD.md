# PRD - Todo 앱

> 상태: 초안
> 근거 문서: docs/IDEA.md

## 1. 목표
- 혼자 쓰는 간단한 할 일 목록 웹 앱을 만든다.
- 할 일을 추가하고, 보고, 완료 표시하고, 삭제하는 기본 흐름을 빠르게 쓸 수 있게 한다.
- 새로고침해도 데이터가 남게 한다 (v0.3).
- 버전 로드맵(v0.1 → v1.0)을 따라 단계적으로 완성하면서 웹 앱 개발을 배운다.

## 2. 대상 사용자
- 자기 할 일을 혼자 관리하는 개인 사용자 1명
- 로그인 없이 공개 배포되므로, URL을 아는 누구나 접속해 보고 수정하고 삭제할 수 있다.
  - 따라서 사용자는 개인 정보를 적지 않는다는 전제로 쓴다.

## 3. 기능 목록

| ID | 기능 | 설명 | 도입 버전 |
|------|------|------|------|
| F-01 | 할 일 추가 | 제목을 입력해 새 할 일을 추가한다 | v0.1 |
| F-02 | 할 일 목록 보기 | 할 일을 만든 시간 기준 최신순으로 보여준다 | v0.1 |
| F-03 | 완료/미완료 전환 | 체크박스로 완료 상태를 바꾼다 | v0.1 |
| F-04 | 할 일 삭제 | 할 일을 확인 창 없이 바로 삭제한다 | v0.1 |
| F-05 | 빈 목록 문구 | 목록이나 필터 결과가 비면 "할 일이 없습니다"를 보여준다 | v0.1 |
| F-06 | 요청 실패 문구 | 서버 요청이 실패하면 에러 문구를 보여준다 | v0.2 |
| F-07 | 데이터 유지 | 새로고침하거나 서버를 재시작해도 데이터가 남아 있다 | v0.3 |
| F-08 | 필터 | 전체 / 진행 중 / 완료로 목록을 걸러 본다 | v0.4 |
| F-09 | 할 일 수정 | 이미 만든 할 일을 수정한다 | v0.4 |

### 기능별 세부 규칙

**F-01 할 일 추가**
- 제목은 필수이다.
- 제목의 앞뒤 공백을 잘라낸 뒤 1~100자여야 한다.
- 공백만 있는 제목은 추가하지 않고 "제목을 입력해 주세요."를 보여준다.
- 100자를 넘으면 추가하지 않고 "제목은 100자 이하로 입력해 주세요."를 보여준다.
- 같은 제목이 이미 있어도 추가할 수 있다.

**F-02 할 일 목록 보기**
- 만든 시간 기준 최신순으로 정렬한다.
- 완료해도 목록에서의 자리는 그대로 유지한다.

**F-03 완료/미완료 전환**
- 체크박스를 누르면 완료와 미완료가 번갈아 바뀐다.
- 상태가 바뀌어도 정렬 위치는 바뀌지 않는다 (F-02).

**F-04 할 일 삭제**
- 확인 창 없이 바로 삭제한다.

**F-05 빈 목록 문구**
- 전체 목록이 비었을 때 "할 일이 없습니다"를 보여준다.
- 필터(F-08) 결과가 비었을 때도 똑같이 "할 일이 없습니다"를 보여준다. (필터는 v0.4부터)

**F-06 요청 실패 문구**
- 추가, 조회, 전환, 삭제, 수정 요청이 실패하면 "요청에 실패했습니다. 다시 시도해 주세요."를 보여준다.
- 수정 요청 실패는 F-09가 생기는 v0.4부터 적용한다.

**F-07 데이터 유지**
- v0.1: 브라우저 메모리에 저장하므로 새로고침하면 데이터가 사라진다.
- v0.2: 서버 메모리에 저장하므로 새로고침이나 재시작 때 데이터가 사라질 수 있다.
- v0.3: DB(Postgres)에 저장하므로 새로고침해도 데이터가 유지된다.

**F-08 필터 (v0.4)**
- 화면에는 전체 / 진행 중 / 완료로 표시하고, 하나를 골라 목록을 걸러 본다.
- "진행 중"은 미완료와 같은 뜻이다.

**F-09 할 일 수정 (v0.4)**
- 제목만 수정할 수 있다.
- 제목을 더블클릭하면 수정할 수 있다.
- F-01과 똑같은 제목 규칙을 적용한다.
  - 앞뒤 공백을 잘라낸 뒤 1~100자여야 한다.
  - 공백만 있으면 저장하지 않고 "제목을 입력해 주세요."를 보여준다.
  - 100자를 넘으면 저장하지 않고 "제목은 100자 이하로 입력해 주세요."를 보여준다.

## 6. 성공 기준
- F-01~F-09가 각 도입 버전에서 3장의 세부 규칙대로 동작한다.
- 입력 검증이 지켜진다.
  - 공백만 있는 제목은 추가되지 않고 "제목을 입력해 주세요."가 보인다.
  - 앞뒤 공백을 잘라낸 뒤 100자를 넘는 제목은 추가되지 않고 "제목은 100자 이하로 입력해 주세요."가 보인다.
  - 중복 제목은 추가된다.
  - 수정(F-09)할 때도 같은 검증이 적용된다.
- 목록이 항상 만든 시간 기준 최신순이고, 완료 상태를 바꿔도 순서가 유지된다.
- 빈 목록일 때는 "할 일이 없습니다"가, 서버 요청이 실패하면 "요청에 실패했습니다. 다시 시도해 주세요."가 보인다.
- v0.3부터 새로고침해도 데이터가 유지된다.
- v1.0에서 Vercel에 배포되어 공개 URL로 접속해 쓸 수 있다.
- docs/TEST_CASES.md의 테스트가 모두 통과한다.

## 7. 결정 사항
IDEA.md에 없던 내용을 확인해 정한 것이다.
- **F-09 수정:** 제목만 수정할 수 있다. 제목을 더블클릭해서 수정한다. 앞뒤 공백 제거와 1~100자 규칙을 추가할 때와 똑같이 적용한다.
- **F-08 필터:** "진행 중"은 미완료와 같은 뜻이다. 화면에는 전체 / 진행 중 / 완료로 표시한다.
- **에러 메시지 문구**

  | 상황 | 문구 |
  |------|------|
  | 공백만 입력 | 제목을 입력해 주세요. |
  | 100자 초과 | 제목은 100자 이하로 입력해 주세요. |
  | 서버 요청 실패 | 요청에 실패했습니다. 다시 시도해 주세요. |

- **공백만 입력했을 때:** 추가하지 않고 "제목을 입력해 주세요."를 보여준다.

## 8. 용어 설명
- **PRD:** Product Requirements Document(제품 요구사항 문서)의 줄임말이다. 무엇을 왜 만드는지 정리한 문서이다.
- **근거 문서:** 이 문서를 쓸 때 바탕으로 삼은 문서이다. 여기서는 docs/IDEA.md이다.
- **도입 버전:** 그 기능을 처음 만드는 버전이다.
- **N장 (예: 3장):** 이 문서의 N번 섹션을 말한다. 예를 들어 "3장"은 "## 3. 기능 목록"이다.
- **US-01:** 사용자 스토리(User Story)의 번호이다. 기능 ID(F-01)와 구분하려고 붙였다.
- **요청:** 화면(브라우저)이 서버에게 "이 일을 해 줘"라고 보내는 것이다. 서버는 그 결과를 돌려준다.
- **조회:** 저장된 데이터를 불러와서 보는 것이다. 여기서는 할 일 목록을 불러오는 것을 말한다.
- **전환:** 상태를 반대로 바꾸는 것이다. 여기서는 완료와 미완료를 바꾸는 것을 말한다.
- **브라우저 메모리:** 내 브라우저 탭 안에 잠깐 저장하는 곳이다. 새로고침하면 사라진다.
- **서버 메모리:** 서버 프로그램 안에 잠깐 저장하는 곳이다. 서버가 꺼지거나 다시 켜지면 사라진다.
- **서버 재시작:** 서버 프로그램을 껐다가 다시 켜는 것이다.
- **DB (데이터베이스):** 데이터를 오래 보관하는 저장소이다. 새로고침하거나 서버를 재시작해도 데이터가 남는다.
- **Postgres:** 이 프로젝트에서 쓰는 DB 종류의 이름이다.
- **입력 검증:** 사용자가 입력한 값이 규칙에 맞는지 확인하는 것이다. 예: 제목이 1~100자인지 확인한다.
- **URL:** 웹 페이지 주소이다. 예: https://example.com
- **공개 배포:** 인터넷에 올려서 주소(URL)를 아는 누구나 접속할 수 있게 하는 것이다.
- **Vercel:** 웹 앱을 인터넷에 올려 주는 서비스 이름이다.
