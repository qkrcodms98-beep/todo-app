# TRD - Todo 앱

> 상태: 초안
> 근거 문서: docs/PRD.md, CLAUDE.md
> TRD는 Technical Requirements Document(기술 요구사항 문서)의 줄임말이다. PRD의 기능을 어떤 기술로 어떻게 만들지 정리한다.

## 1. 기술 스택과 고른 이유

| 분류 | 기술 | 고른 이유 |
|------|------|------|
| 프레임워크 | Next.js 15 (App Router) | 화면과 서버(API)를 한 프로젝트 안에서 같이 만들 수 있다. |
| 화면 라이브러리 | React 19 | 화면을 작은 조각(컴포넌트)으로 나눠 만들 수 있다. Next.js가 React 위에서 동작한다. |
| 언어 | TypeScript (strict) | 값의 종류(타입)를 미리 정해서, 실수를 실행 전에 찾을 수 있다. strict는 가장 엄격하게 검사하는 설정이다. |
| 스타일 | Tailwind CSS | CSS 파일을 따로 만들지 않고 클래스 이름만으로 디자인할 수 있다. |
| DB | Postgres | 할 일을 오래 보관하는 데이터베이스이다 (PRD F-07). |
| DB 호스팅 | Neon | Postgres를 내 컴퓨터에 직접 설치하지 않고 인터넷에서 빌려 쓸 수 있다. |
| ORM | Drizzle ORM | SQL을 직접 쓰지 않고 TypeScript 코드로 DB를 다룰 수 있다. 타입 검사도 된다. |
| 입력 검증 | Zod | "제목은 1~100자" 같은 규칙을 한 곳에 적어 두고 화면과 서버에서 같이 쓸 수 있다. |
| 테스트 | Jest | 코드가 의도대로 동작하는지 자동으로 확인한다. |
| 화면 테스트 | React Testing Library | 사용자가 보는 화면 기준으로(버튼 누르기, 문구 확인) 테스트할 수 있다. |
| 배포 | Vercel | Next.js를 만든 회사의 배포 서비스이다. 앱을 인터넷에 올리는 데 쓴다 (v1.0). |

## 2. 폴더 구조

| 폴더 | 역할 |
|------|------|
| app/ | 페이지와 API 라우트 |
| src/components/ | 화면 컴포넌트 (입력창, 목록, 할 일 한 줄 등) |
| src/lib/ | 서버 로직, DB, 화면과 서버가 함께 쓰는 검증 규칙 |
| src/types/ | 화면과 서버가 같이 쓰는 타입 |
| docs/ | 명세 문서 |

| 버전 | 저장 위치 | 새로고침하면 |
|------|------|------|

| v0.2 | 서버 메모리 (API 라우트 안의 변수) | 남지만, 서버를 재시작하면 사라질 수 있다 |
| v0.3~ | Postgres (Neon) | 남는다 |

## 4. 동작 흐름 (v0.3 기준)

### 4-1. 페이지를 열 때 목록 불러오기

1. **페이지 열기:** 사용자가 앱 주소로 들어오거나 새로고침한다.
2. **요청 보내기:** 화면이 서버의 API 라우트로 목록을 달라는 요청을 보낸다.
3. **DB에서 읽기:** API 라우트가 src/lib의 서버 로직을 부르고, 서버 로직이 Drizzle로 Postgres(Neon)에서 할 일을 만든 시간 기준 최신순으로 읽어온다. 만든 시간이 같으면 id가 큰 것을 위에 둔다 (PRD F-02).
4. **응답 돌려주기:** 서버가 읽어온 할 일 목록을 화면에 돌려준다.
5. **화면 표시:** 화면이 목록을 보여준다. 보여줄 할 일이 없으면 "할 일이 없습니다"를 보여준다 (PRD F-05).
6. **실패했을 때:** 네트워크 오류나 서버 오류로 2~4단계가 실패하면 "요청에 실패했습니다. 다시 시도해 주세요."를 보여준다 (PRD F-06).

```
[페이지 열기]
      │ ① 접속 / 새로고침
      ▼
[화면 컴포넌트]
      │ ② 목록 요청
      ▼
[API 라우트 (app/)]
      │
      ▼
[서버 로직 (src/lib/)] ── ③ Drizzle로 최신순 읽기
      │
      ▼
[Postgres (Neon)]
      │ ④ 할 일 목록 응답
      ▼
[화면 컴포넌트] ── ⑤ 목록 표시 (비면 "할 일이 없습니다") / ⑥ 실패 시 실패 문구
```

### 4-2. "추가" 버튼을 누른 뒤 DB에 저장되기까지

1. **입력:** 사용자가 입력창에 제목을 쓰고 "추가" 버튼을 누른다.
2. **화면에서 검증:** 화면 컴포넌트가 src/lib의 Zod 규칙으로 제목을 검사한다. 이때 앞뒤 공백을 잘라낸다. 글자 수는 JavaScript 문자열 길이(`.length`) 기준으로 센다.
   - 공백만 있으면 요청을 보내지 않고 "제목을 입력해 주세요."를 보여준다.
   - 100자를 넘으면 요청을 보내지 않고 "제목은 100자 이하로 입력해 주세요."를 보여준다.
3. **요청 보내기:** 검사를 통과하면 화면이 서버의 API 라우트로 제목을 담아 요청을 보낸다.
4. **서버에서 다시 검증:** API 라우트가 같은 Zod 규칙으로 한 번 더 검사한다. 화면을 거치지 않고 바로 오는 요청도 막기 위해서다.
   - 규칙에 걸리면 저장하지 않고 실패 응답을 돌려준다. 화면은 2단계와 똑같은 문구("제목을 입력해 주세요." 또는 "제목은 100자 이하로 입력해 주세요.")를 보여준다.
5. **DB에 저장:** 검사를 통과하면 src/lib의 서버 로직이 Drizzle로 Postgres(Neon)에 새 할 일을 저장한다. 만든 시간은 서버 로직이 넣지 않고 DB 기본값 `now()`가 넣는다.
6. **응답 돌려주기:** 서버가 저장된 할 일을 화면에 돌려준다.
7. **화면 갱신:** 새 할 일은 현재 필터 조건에 맞을 때만 목록 맨 위에 보인다 (PRD F-02, F-08). 필터는 v0.4부터이고, 그 전에는 항상 맨 위에 보인다.
8. **실패했을 때:** 네트워크 오류나 서버 오류로 3~6단계가 실패하면 "요청에 실패했습니다. 다시 시도해 주세요."를 보여준다 (PRD F-06). 제목 규칙에 걸린 경우(4단계)에는 이 문구를 쓰지 않는다.

```
[입력창 + 추가 버튼]
      │ ① 제목 입력, 버튼 클릭
      ▼
[화면 컴포넌트] ── ② Zod 검사 실패 → 제목 규칙 문구 표시
      │ ③ 요청
      ▼
[API 라우트 (app/)] ── ④ Zod 검사 실패 → 실패 응답 → 화면에 제목 규칙 문구 표시
      │
      ▼
[서버 로직 (src/lib/)] ── ⑤ Drizzle로 저장
      │
      ▼
[Postgres (Neon)]
      │ ⑥ 저장된 할 일 응답
      ▼
[화면 컴포넌트] ── ⑦ 필터 조건에 맞으면 맨 위에 표시 / ⑧ 네트워크·서버 오류 시 실패 문구
```

### 4-3. 다른 동작

| 동작 | 제목 검증 단계 (4-2의 2, 4단계) | 나머지 흐름 |
|------|------|------|
| 완료 전환 (F-03) | 없음 | 요청 → DB에서 완료 상태 변경 → 응답 → 화면 갱신 |
| 삭제 (F-04) | 없음 | 요청 → DB에서 삭제 → 응답 → 화면에서 제거 |
| 수정 (F-09, v0.4) | 있음 (추가와 같은 규칙, 같은 문구) | 요청 → DB에서 제목 변경 → 응답 → 화면 갱신 |

- 세 동작 모두 네트워크 오류나 서버 오류로 실패하면 "요청에 실패했습니다. 다시 시도해 주세요."를 보여준다.

## 5. 기술 규칙
- `any` 타입은 쓰지 않는다.
- 제목 검증 규칙(Zod)은 한 곳(src/lib)에 두고 화면과 서버가 같이 쓴다. 추가(F-01)와 수정(F-09)도 같은 규칙을 쓴다.
- 제목 글자 수는 JavaScript 문자열 길이(`.length`) 기준으로 센다.
- DB 접속 정보는 `.env.local`에만 두고 커밋하지 않는다.
- 테스트는 Jest + React Testing Library로 작성하고 `npm test`로 실행한다.

## 6. 다른 문서로 넘기는 것
- 할 일 데이터의 필드 이름과 타입은 docs/DATA_MODEL.md에서 정한다.
- API 주소, 요청 형식, 응답 형식(실패 응답에 어떤 규칙에 걸렸는지 담는 방법 포함)은 docs/API_SPEC.md에서 정한다.
- 컴포넌트 이름과 역할은 docs/COMPONENT_SPEC.md에서 정한다.

## 7. 결정 사항
- **검증 위치:** 화면과 서버 두 곳에서 검증한다. 규칙은 src/lib 한 곳에 두고 같이 쓴다.
- **서버 검증 실패 문구:** 서버에서 제목 규칙에 걸려도 화면 검사와 똑같은 문구를 보여준다.
- **요청 실패 문구:** "요청에 실패했습니다. 다시 시도해 주세요."는 네트워크 오류나 서버 오류일 때만 쓴다.
- **정렬:** 만든 시간 기준 최신순으로 읽고, 만든 시간이 같으면 id가 큰 것을 위에 둔다 (PRD F-02).
- **제목 글자 수 세는 기준:** JavaScript 문자열 길이(`.length`)로 센다. 이 기준은 DB가 세는 방법보다 엄격해서, Zod를 통과한 제목은 DB에서 거부되지 않는다. 자세한 내용은 docs/DATA_MODEL.md에 적는다.
- **만든 시간 저장:** 서버 로직이 아니라 DB 기본값 `now()`가 넣는다.

## 8. 용어 설명
- **프레임워크:** 앱을 만드는 기본 틀이다. 정해진 규칙과 폴더 구조에 맞춰 코드를 쓰면 틀이 알아서 연결해 준다. 예: Next.js
- **라이브러리:** 필요한 기능을 가져다 쓰는 도구 모음이다. 프레임워크보다 범위가 좁고, 내가 원할 때 불러 쓴다. 예: React, Zod
- **ORM:** Object-Relational Mapping의 줄임말이다. DB의 표를 코드 속 객체처럼 다루게 해 주는 도구이다. 예: Drizzle
- **SQL:** DB에게 "이 데이터를 저장해 줘, 읽어 줘"라고 명령하는 언어이다.
- **호스팅:** 서버나 DB를 내 컴퓨터 대신 다른 회사의 컴퓨터에 두고 인터넷으로 쓰는 것이다.
- **CSS:** 화면의 색, 크기, 위치 같은 모양을 정하는 언어이다.
- **클래스 이름:** HTML 요소에 붙이는 이름표이다. Tailwind에서는 `text-red-500`처럼 이름표 자체가 모양을 뜻한다.
- **API:** 프로그램끼리 데이터를 주고받는 약속된 창구이다.
- **API 라우트:** Next.js에서 화면의 요청을 받는 서버 쪽 입구이다. app/ 폴더 안에 만든다.
- **상태 (React 상태):** 화면이 기억하고 있는 값이다. 값이 바뀌면 화면이 다시 그려진다. 예: 지금 보이는 할 일 목록
- **변수:** 값을 담아 두는 이름 붙은 상자이다.
- **응답:** 요청을 받은 서버가 결과를 돌려주는 것이다.
- **실패 응답:** 서버가 "요청대로 처리하지 못했다"고 돌려주는 응답이다. 예: 제목 규칙에 걸렸을 때
- **네트워크 오류:** 인터넷 연결이 끊기는 등의 이유로 요청이 서버에 닿지 못하거나 응답이 돌아오지 못한 경우이다.
- **서버 오류:** 요청은 서버에 닿았지만 서버 안에서 문제가 생겨 처리하지 못한 경우이다. 예: DB 연결이 끊김
- **갱신:** 바뀐 내용을 화면에 새로 반영해 보여주는 것이다.
- **화면을 거치지 않고 바로 오는 요청:** 앱 화면을 쓰지 않고 다른 도구로 API 라우트에 직접 보내는 요청이다. 이런 요청은 화면 검사를 건너뛰므로 서버에서도 검사한다.
- **그림 읽는 법:** 네모 칸 `[ ]`은 프로그램의 한 부분이다. `│`와 `▼`는 다음 단계로 넘어가는 방향이고, `──`는 그 단계에서 일어나는 일이다. ①~⑧은 본문 단계 번호이다.
- **커밋:** git으로 지금까지 바꾼 내용을 기록으로 저장하는 것이다. 커밋한 내용은 나중에 공개 저장소에 올라갈 수 있다.
- **.env.local:** DB 접속 정보처럼 비밀 값을 적어 두는 파일이다. 커밋하지 않아서 다른 사람에게 공개되지 않는다.
- **id:** 할 일 하나하나에 붙는 번호이다. 나중에 만든 할 일일수록 번호가 크다.
- **JavaScript 문자열 길이 (`.length`):** JavaScript가 글자 수를 세는 방법이다. 한글, 영어, 숫자는 한 글자를 1자로 세지만, 이모지(예: 😀)는 2자로 셀 때가 있다.
- **DB 기본값:** 값을 따로 주지 않았을 때 DB가 자동으로 넣는 값이다.
- **now():** 지금 이 순간의 시간을 뜻하는 DB 함수이다. 기본값으로 쓰면 새 할 일을 저장하는 순간의 시간이 들어간다.
